# T037 — Test the halts frame by frame inside a Flame game

## Description

T034–T036 together, as T009 tested the wave-1 loop: `EventQueue`, `WorldHalts`, `StepClock`,
`GameLoop` and `LoopComponent` in a real Flame game, driven by the halt events of change-02. World
and interface systems and a drain stand in for the features and `core/input`; Flame is advanced
frame by frame with a fixed `dt`, and nothing is mocked. The tests join T009's file. The first test
across `input` → `loop` comes with input in wave 2.

## Preconditions

- `test/integration/loop_frame_test.dart` holds T009's helper `gameStepping(EventQueue queue,
  List<SystemStep> systems)` and its three tests.

## Constraints

- T009's three tests keep their names and assertions; `gameStepping` may take further optional
  parameters for the interface systems and the drain.

## Acceptance criteria

| Test file | Test name | Assertion |
|---|---|---|
| `test/integration/loop_frame_test.dart` | the interface steps on while the map halts the world | `MapOpened()` published through the `EventSink`, then three `game.update(1 / 60)`: the world system steps 0 times and the interface system 3 times, each `dt` within 1e-9 of 1/60. `MapClosed()` published, then one `game.update(1 / 60)`: the world system has stepped once and the interface system 4 times. |
| `test/integration/loop_frame_test.dart` | two halts hold the world until both end | `PauseOpened()` and `DialogueOpened(spirit: EntityId(1))` published, one `game.update(1 / 60)`; `PauseClosed()`, one update; `DialogueClosed(spirit: EntityId(1))`, one update: the world system steps only in the third frame. |
| `test/integration/loop_frame_test.dart` | an unmatched resume never frees the world | `MapOpened()` then `AbilityChosen(ability: AbilityId.web, slotIndex: 0)` published, then three `game.update(1 / 60)`: the world system steps 0 times. |
| `test/integration/loop_frame_test.dart` | a command drained during a pause frees the world that frame | `PauseOpened()` published before the first frame; the drain publishes `PauseClosed()` on its third call. Over three `game.update(1 / 60)`, the world system steps only in the third frame. |
