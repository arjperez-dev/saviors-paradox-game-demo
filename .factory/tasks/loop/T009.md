# T009 — Test the loop frame by frame inside a Flame game

## Description

The loop as the composition root will use it, in a real Flame game: `EventQueue`, `StepClock`,
`GameLoop` and `LoopComponent` together. Systems stand in for features and publish the contract
events features will publish. The tests advance Flame frame by frame with a fixed `dt` and assert
what the systems receive. Nothing is mocked. The first test across two modules (`input` → `loop`)
comes in wave 2, once both are on `main`.

## Interfaces

| File | Symbol | Role | Signature |

| `lib/core/loop/presentation/loop_component.dart` | `LoopComponent` | uses | `LoopComponent(GameLoop loop)` |

## Acceptance criteria

| Test file | Test name | Assertion |
|---|---|---|
| `test/integration/loop_frame_test.dart` | a hitstop raised by one system holds every system for its duration | In a `testWithFlameGame`, system a publishes `HitstopStarted(duration: Seconds(0.05))` on its first step only. Over six `game.update(0.02)`, system b steps four times, with steps within 1e-9 of 0.02, 0.01, 0.02 and 0.02. |
| `test/integration/loop_frame_test.dart` | a pause opened between frames freezes the systems until it closes | `PauseOpened` published through the `EventSink` before three `game.update(1 / 60)`: no system steps. `PauseClosed` published, then one `game.update(1 / 60)`: every system steps once. |
| `test/integration/loop_frame_test.dart` | the same frames give the same steps | Two fresh games fed the same sequence of `game.update` values (0.02, 0.5, 1/60, 0.03) record equal lists of system steps. |
