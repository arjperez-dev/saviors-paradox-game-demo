# T085 — Queue the attacks a body strikes or throws

## Description

`EngagementQueue`, the use case behind the `AttackResolver` contract. It replaces the stub.
- `strike` reads the attack and the attacker's immunities, asks the roster for the bodies the
  area can reach (within its half-diagonal), and adds one pending `Engagement` per body. Whether
  each one lands is the engagement's rule, resolved by `StepEngagements`.
- `launch` loads `Flights`, launches the missile into it, and saves it.

## Preconditions

- On `main`, `lib/features/combat/application/engagement_queue.dart` is a stub whose two methods
  do nothing.
- T074's and T079's repositories, T080's reading functions and mocks, and T081's
  `CombatantRoster` are on `feat/combat`.

## Constraints

- No rule and no state of its own. Each method changes one aggregate.
- Tests use a real `CombatantRoster` holding `MockCombatant`s, a `MockEngagementRepository` whose
  `add` arguments are captured, and a `MockFlightsRepository` returning a real `Flights`.

## Implementation

```dart
// lib/features/combat/application/engagement_queue.dart — replaced whole
import 'dart:math' as math;

import 'package:saviors_paradox/core/contracts/ports/attack.dart';
import 'package:saviors_paradox/core/contracts/ports/attack_resolver.dart';
import 'package:saviors_paradox/core/contracts/ports/projectile.dart';
import 'package:saviors_paradox/features/combat/application/combatant_roster.dart';
import 'package:saviors_paradox/features/combat/application/contract_reading.dart';
import 'package:saviors_paradox/features/combat/application/ports/engagement_repository.dart';
import 'package:saviors_paradox/features/combat/application/ports/flights_repository.dart';
import 'package:saviors_paradox/features/combat/domain/engagement.dart';

/// Takes the attacks bodies strike and throw; they resolve when combat
/// steps.
final class EngagementQueue implements AttackResolver {
  EngagementQueue({
    required CombatantRoster roster,
    required EngagementRepository engagements,
    required FlightsRepository flights,
  }) : _roster = roster,
       _engagements = engagements,
       _flights = flights;

  final CombatantRoster _roster;
  final EngagementRepository _engagements;
  final FlightsRepository _flights;

  @override
  void strike(Attack attack) {
    final strike = readStrike(attack);
    final attacker = readImmunities(_roster.byId(attack.attacker));
    final area = attack.area;
    final reach = math.sqrt(
      area.halfWidth * area.halfWidth + area.halfHeight * area.halfHeight,
    );
    for (final body in _roster.near(area.centre, reach)) {
      _engagements.add(
        Engagement(
          strike: strike,
          defender: readDefender(body),
          attacker: attacker,
        ),
      );
    }
  }

  @override
  void launch(Projectile projectile) {
    final flights = _flights.load();
    flights.launch(readMissile(projectile));
    _flights.save(flights);
  }
}
```

## Acceptance criteria

The attack is attacker `EntityId(1)`, side `foe`, melee, plain, area
`WorldBox(centre: Vec2(0, 0), halfWidth: 20, halfHeight: 20)`, damage 10, blockable.

| Test file | Test name | Assertion |
|---|---|---|
| `test/features/combat/application/engagement_queue_test.dart` | a strike queues one engagement per body in reach | With bodies at `Vec2(30, 0)` and `Vec2(-30, 0)` (half 10 × 10) and one at `Vec2(500, 0)`, `strike` calls `engagements.add` twice. |
| `test/features/combat/application/engagement_queue_test.dart` | a queued engagement resolves against the body struck | With one Akeris body `EntityId(2)` at `Vec2(25, 0)` (half 10 × 10, unguarded), the captured engagement's `resolve()` is a `StrikeLanded` with `target: EntityId(2)`. |
| `test/features/combat/application/engagement_queue_test.dart` | a strike reads the attacker's immunities | With the attacker registered and immune to ice, and Akeris guarded `RaisedShield(shield: ice, raisedFor: Seconds(0.1))`, the captured engagement resolves to a `StrikeBlocked` whose affliction's kind is `slowed`. |
| `test/features/combat/application/engagement_queue_test.dart` | a strike reaching nobody queues nothing | With no body in reach, `add` is never called. |
| `test/features/combat/application/engagement_queue_test.dart` | a launch puts the projectile in the air | `launch(projectile)` leaves the loaded `Flights` with `flyingCount` 1, and `flights.save` is called once with it. |
