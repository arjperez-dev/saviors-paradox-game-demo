# T074 — Keep the pending engagements

## Description

The repository of the `Engagement` aggregate (architecture §4, checklist A14). It holds the
engagements struck and not yet resolved, oldest first: the port lives in `application/ports/`,
the in-memory implementation in `infrastructure/`. `EngagementQueue` adds to it, and
`StepEngagements` takes from it.

## Preconditions

- T073's `Engagement` is on `feat/combat`.

## Constraints

- Each engagement is handed back whole, once. `next()` allocates nothing (a `ListQueue`).

## Implementation

```dart
// lib/features/combat/application/ports/engagement_repository.dart — new
import 'package:saviors_paradox/features/combat/domain/engagement.dart';

/// The engagements struck and not yet resolved.
abstract interface class EngagementRepository {
  /// Keeps [engagement] until it is taken.
  void add(Engagement engagement);

  /// Takes the oldest pending engagement, or null when none waits.
  Engagement? next();
}
```

```dart
// lib/features/combat/infrastructure/in_memory_engagement_repository.dart — new
import 'dart:collection';

import 'package:saviors_paradox/features/combat/application/ports/engagement_repository.dart';
import 'package:saviors_paradox/features/combat/domain/engagement.dart';

/// The pending engagements, held in memory for the zone.
final class InMemoryEngagementRepository implements EngagementRepository {
  final ListQueue<Engagement> _pending = ListQueue<Engagement>();

  @override
  void add(Engagement engagement) => _pending.addLast(engagement);

  @override
  Engagement? next() => _pending.isEmpty ? null : _pending.removeFirst();
}
```
