# T139 — Test Akeris moving through a generated zone

## Description

The wave's slice tested with the loop (testing.md §7): Akeris placed at a generated zone 1's start,
moving and colliding there, hurt by a hit, hanging on a chain. It uses only what is on `main` plus
akeris's own tasks (operator, 2026-10-17). Built all real:
- `core/loop`: an `EventQueue` and a `GameLoop`.
- dungeon, as on `main`: `InMemoryZoneRepository`,
  `SeededZoneGenerator(kits: [SuspendedSanctuaryKit()])`, `ZoneCollisionWorld`, `StepZone`. On
  `main`, `PresenceInZone` is a stub and `isStaticSolidAt` and `carry` answer `false` and zero.
- akeris: `InMemoryAkerisRepository(Akeris(feet: Vec2.zero))`, `TerrainOfWorld`, `ReportAkeris`,
  `StepAkeris`, `ControlAkeris`, `HearHits`, and `EnterZone` reading `stepZone.state`.

The systems step in the order `StepZone`, `StepAkeris`. The hit is a `HitLanded` published on the
queue, as combat would publish it. The chain is a `MockChainBlades` whose `pull` is `const NoPull()`
unless a test says.

## Preconditions

- On `main`: `EventQueue`, `StepClock`, `GameLoop`; dungeon as wave 4 integrated it, with change-05.

## Acceptance criteria

The zone is `generate(ZoneNumber.first, Seed(42))`, called before the first frame; a frame is
`loop.advance(Seconds(1 / 60))`; a `GameEvent` handler records `published`; commands are published
on the queue before a frame.
