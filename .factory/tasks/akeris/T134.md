# T134 — Take what an altar holds

## Description

G next to an altar picks up what it holds (`controls.md` G17, `items.md` §2). Akeris decides the
body action; dungeon decides the reach and the altar (architect change-04, `ports-altars`). On
`Take`, when the root can pick up, the use case asks `Altars.takeWithin(feet)`. Only when an item
came back does Akeris hold still for the pickup. inventory and arsenal learn the item from dungeon's
`ItemTaken`, never from akeris. This use case is built against the contract, mocked in its tests;
dungeon's T141 implements `takeWithin` on its own branch.

## Preconditions

- On `main`: `EventQueue` (core/loop).

## Constraints

- No rule: the root says whether he can take; the port says whether there was an item.

## Implementation

```dart
// lib/features/akeris/application/take_from_altar.dart — new
import 'package:saviors_paradox/core/contracts/events/player_command.dart';
import 'package:saviors_paradox/core/contracts/ports/altars.dart';
import 'package:saviors_paradox/core/contracts/ports/event_source.dart';
import 'package:saviors_paradox/features/akeris/application/ports/akeris_repository.dart';

/// G next to an altar: Akeris picks up what it holds (items.md §2).
final class TakeFromAltar {
  TakeFromAltar(this._akeris, this._altars, EventSource commands) {
    commands.subscribe<Take>((_) => take());
  }

  final AkerisRepository _akeris;
  final Altars _altars;

  void take() {
    final akeris = _akeris.load();
    if (!akeris.canPickUp || _altars.takeWithin(akeris.feet) == null) {
      return;
    }
    akeris.pickUp();
    _akeris.save(akeris);
  }
}
```
