# T002 — Configure the Dart analysis options

## Description

The analyzer, the linter and the formatter, in the one file Dart reads for all three. It turns on
the three strict language modes of `coding-standards.md` §6, and it adds to `flutter_lints` the rules
that make that document's rules mechanical. The formatter keeps the 80 columns of §3 and the
architect's trailing commas.

## Constraints

- No file under `lib/` or `test/` changes. A contract or stub that the analyzer rejects is a stop
  with `needs: architect`. A kernel test of T001 that it rejects is a stop with `needs: planner`.
- `exclude` holds exactly what `flutter pub get` writes there on its own, so no later `pub get`
  changes the file.

## Implementation

```yaml
# analysis_options.yaml — new
# 08-engineering/coding-standards.md §6, §10: strict modes, analyze clean with --fatal-infos.
include: package:flutter_lints/flutter.yaml

analyzer:
  exclude:
    - build/**
    - windows/**
  language:
    strict-casts: true
    strict-inference: true
    strict-raw-types: true

formatter:
  page_width: 80
  trailing_commas: preserve

linter:
  rules:
    - always_declare_return_types
    - always_use_package_imports
    - avoid_catches_without_on_clauses
    - avoid_dynamic_calls
    - avoid_positional_boolean_parameters
    - directives_ordering
    - only_throw_errors
    - prefer_final_fields
    - prefer_final_locals
    - prefer_single_quotes
    - type_annotate_public_apis
    - unawaited_futures
```
