# T002 — Configure the Dart analysis options

## Description

The analyzer, the linter and the formatter, in the one file Dart reads for all three. It turns on
the three strict language modes of `coding-standards.md` §6, and it adds to `flutter_lints` the rules
that make that document's rules mechanical. The formatter keeps the 80 columns of §3 and the
architect's trailing commas. Two of T001's kernel tests are brought under the new rules: one
comparison the lints reject, and four lines the formatter wraps.

## Preconditions

- T001 is integrated on `feat/tooling`. In `test/core/contracts/kernel/result_test.dart`, test
  `a success never equals a failure` declares `const success = Success<int, int>(1);` and
  `const failure = Failure<int, int>(1);`, then asserts `expect(success == failure, isFalse);`.
  `unrelated_type_equality_checks`, which `flutter_lints` turns on through `package:lints/core.yaml`,
  flags that comparison.
- In `test/core/contracts/kernel/seconds_test.dart`, the tests `clamps a duration to a maximum` and
  `clamps a duration to a minimum` each hold two one-line `expect` calls of more than 80 columns.

## Constraints

- No file under `lib/` changes. A contract or stub that the analyzer rejects is a stop with
  `needs: architect`.
- The two test files change only as the `Implementation` shows: every test name and every asserted
  value stays as T001 wrote it.
- `exclude` holds `build/**` and `windows/**`, the two folders the Flutter tools generate (the build
  output, and the runner T004 generates), and nothing else.
- No `// ignore:` and no rule turned off.

## Implementation

```yaml
# analysis_options.yaml — new
# 08-engineering/coding-standards.md §6, §10: strict modes, analyze clean with --fatal-infos.
include: package:flutter_lints/flutter.yaml

analyzer:
  exclude:
    - build/**
    - windows/**
  language:
    strict-casts: true
    strict-inference: true
    strict-raw-types: true

formatter:
  page_width: 80
  trailing_commas: preserve

linter:
  rules:
    - always_declare_return_types
    - always_use_package_imports
    - avoid_catches_without_on_clauses
    - avoid_dynamic_calls
    - avoid_positional_boolean_parameters
    - directives_ordering
    - only_throw_errors
    - prefer_final_fields
    - prefer_final_locals
    - prefer_single_quotes
    - type_annotate_public_apis
    - unawaited_futures
```

```dart
// test/core/contracts/kernel/result_test.dart — edited, test `a success never equals a failure`
// before:
      const success = Success<int, int>(1);
      const failure = Failure<int, int>(1);
// after: both typed as the sealed parent, so `==` compares two Results.
      const Result<int, int> success = Success(1);
      const Result<int, int> failure = Failure(1);
// The assertion `expect(success == failure, isFalse);` stays unchanged.
```
