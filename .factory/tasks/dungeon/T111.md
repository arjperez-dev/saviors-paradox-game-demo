# T111 — Let the altars take the event sink they will publish to

## Description

Step (i) of three (planner wave-05 `altars-sink-expand-contract`). `ZoneAltars` will publish
`ItemTaken`, so it needs an `EventSink`. `test/integration/dungeon_zone_test.dart` calls
`ZoneAltars(zones)` and belongs to module `integration`. So the constructor first takes the sink as
an optional positional parameter, and both calls compile. T140 then switches that test to the new
call, and T141 makes the sink required and implements `takeWithin`.

The sink is not kept yet: `takeWithin` stays the stub, so nothing could publish through it, and an
unused field would fail `flutter analyze --fatal-infos`. This step never reaches `main`: T141
removes it on `feat/dungeon`, before the pull request.

## Preconditions

- On `main`, `ZoneAltars(this._zones)` implements `Altars` with the real `returnTo` (T104) and the
  stub `takeWithin` returning null (architect change-04).

## Constraints

- `returnTo` and `takeWithin` are unchanged.
