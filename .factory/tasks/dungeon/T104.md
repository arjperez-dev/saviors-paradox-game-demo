# T104 — Return an item to its altar

## Description

`ZoneAltars`, the use case behind the `Altars` contract. It replaces the stub. `inventory` calls
it when a hit interrupts the reading of a scroll, which goes back to its altar (`items.md` I4). It
translates the item into a gift, asks the root to lay it on the altar (the root refuses an altar
that holds one), and saves the zone. Taking an item with G comes with the step driven by Akeris's
position.

## Preconditions

- On `main`, `lib/features/dungeon/application/zone_altars.dart` is a stub whose `returnTo` does
  nothing.
- T098's factory, T099's repository and mocks, and T100's `readGift` are on `feat/dungeon`.

## Constraints

- No rule and no state; one aggregate per call.

## Implementation

```dart
// lib/features/dungeon/application/zone_altars.dart — replaced whole
import 'package:saviors_paradox/core/contracts/kernel/entity_id.dart';
import 'package:saviors_paradox/core/contracts/ports/altars.dart';
import 'package:saviors_paradox/core/contracts/state/altar_item.dart';
import 'package:saviors_paradox/features/dungeon/application/ports/zone_repository.dart';
import 'package:saviors_paradox/features/dungeon/application/zone_reading.dart';

/// Lays an item back on its altar when another feature gives it back.
final class ZoneAltars implements Altars {
  ZoneAltars(this._zones);

  final ZoneRepository _zones;

  @override
  void returnTo(EntityId altar, AltarItem item) {
    final zone = _zones.load();
    if (zone == null) {
      return;
    }
    zone.returnTo(altar, readGift(item));
    _zones.save(zone);
  }
}
```
