# T099 — Keep the current zone

## Description

The repository of the `Zone` aggregate (architecture §4, A14): the port in `application/ports/`
and the in-memory implementation in `infrastructure/`. It loads and saves the whole aggregate;
before any zone is generated it holds none. The task also writes `test/features/dungeon/mocks.dart`,
which every later dungeon test imports.

## Preconditions

- T097's `Zone` is on `feat/dungeon`; the test builds its zones with `Zone.of` from layouts of
  T092's `ZoneBuilder`.

## Constraints

- Its one mutable field is the zone it holds, assigned by `save`. Test doubles are `mocktail`
  mocks, all in `mocks.dart`.

## Implementation

```dart
// lib/features/dungeon/application/ports/zone_repository.dart — new
import 'package:saviors_paradox/features/dungeon/domain/zone.dart';

/// Where the zone Akeris is in is kept.
abstract interface class ZoneRepository {
  /// The current zone, whole, or null before any zone is generated.
  Zone? load();

  /// Keeps [zone] as the current zone.
  void save(Zone zone);
}
```

```dart
// lib/features/dungeon/infrastructure/in_memory_zone_repository.dart — new
import 'package:saviors_paradox/features/dungeon/application/ports/zone_repository.dart';
import 'package:saviors_paradox/features/dungeon/domain/zone.dart';

/// The current zone, held in memory for the run.
final class InMemoryZoneRepository implements ZoneRepository {
  Zone? _zone;

  @override
  Zone? load() => _zone;

  @override
  void save(Zone zone) => _zone = zone;
}
```
