# T052 — Give the screens one ink theme at the screen's size

- **Date:** 2026-10-16
- **Outcome:** Added `InkLettering` (the kit's closed set of lettering roles, each a size in hu
  and a colour), `InkThemeData` (the UI scale, lettering and every colour/stroke width the kit
  draws with, in hu, copied from the 06-ui and cinematics sandboxes) and `InkTheme` (a
  `StatefulWidget` that reads the screen's height once per resize through a `LayoutBuilder` and
  hands every widget under it the same `InkThemeData` instance through an `InheritedWidget`,
  rebuilding dependents only when the scale actually changes).
- **Decisions:** none — the task's `Implementation` was put in as written for all three
  production files.
- **Deviations:**
  - `ink_lettering.dart`: the Implementation's inline comment cited `ttMain` as a source of
    `buttonFaint`'s value (30, ink at .45). `ttMain`'s own disabled-menu-item text is actually
    drawn at 34 hu (`06-ui/sandbox/sandbox.html` line 4606), not 30, and no element in either
    cited sandbox draws text at 30 with ink-at-.45. The task's `Implementation` and its
    Acceptance criterion both fix `buttonFaint` at 30 (matching `button`'s own size), so the
    value is unchanged; only the comment is corrected to say `buttonFaint` is `button`'s own
    size, a faint variant, rather than a literal transcription of `ttMain`'s own (larger, 34 hu)
    role, which this enum does not cover. Flagged by the tester; no criterion or interface was
    affected.
  - `ink_theme_test.dart`: the tester found that the "a frame without a resize keeps the theme
    and rebuilds nothing" test, as first written, pumped the exact same `Widget` object twice —
    which Flutter's element diffing skips rebuilding entirely on widget identity, so the test
    passed regardless of whether `_InkThemeState._dataFor`'s memoization worked at all. Rewrote
    the test to pump two different `InkTheme` wrapper instances around the same reader widget, so
    `_InkThemeState.build()` is forced to run again at the same screen height and the cache is
    actually exercised; confirmed by temporarily breaking the memoization and watching the test
    fail, then restoring it and watching it pass.
- **Evidence:** No adaptation to the Implementation's code was needed — it compiled and passed
  against the tree as it stood (T051's `ScreenUiScale`/`UiScale`, and `main`'s `Palette` and
  `Lettering.style`/`Lettering.family`, already existed as the Preconditions describe). Every
  `const` colour and width in `InkThemeData` was checked line-by-line against the cited
  `06-ui/sandbox/sandbox.html` (`sheetAt`, `hudBox`, `ttBox`, `ttMain`, `keyCap`, `ttConfirm`,
  `pmConfirm`) and `01-story/cinematics/sandbox/sandbox.html` (`skipOverlay`), and all matched
  exactly, including the operator's two constraints (the sheet's shadow at darkness .55 in place
  of the sandbox's black; `ttBox`'s .78/.95 fills for every screen). Files touched, all listed in
  `files`: `lib/core/ui/presentation/ink_lettering.dart`, `ink_theme_data.dart`, `ink_theme.dart`;
  `test/core/ui/presentation/ink_lettering_test.dart`, `ink_theme_data_test.dart`,
  `ink_theme_test.dart`. `flutter test` (341 tests) and `flutter analyze --fatal-infos` are clean;
  `dart format` reports no changes.
