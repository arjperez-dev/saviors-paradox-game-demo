# T055 — Generate a sheet's pencil border once from its seed

- **Date:** 2026-10-16
- **Outcome:** `SheetOutline` in `lib/core/ui/domain/sheet_outline.dart`: a value object generating
  a paper sheet's four-corner border (slightly out of square) from its seed and its faint inner
  line, inset 12, from the next seed, both via `PolygonStroke.generate` and `StrokeRandom`, once,
  with unmodifiable corner lists.
- **Decisions:** the tester (run once, before `verify-task`) reported the task's Description
  calling `SheetOutline` "a value object (architecture §4)" — whose rule is "equal by value" — while
  the `Implementation` block overrode neither `operator ==` nor `hashCode`. Closed by adding both,
  comparing `border` and `inner` element-wise, with a comment naming `architecture.md §4`, plus one
  extra test, `sheets with equal corners are equal by value`, beyond the acceptance table. This
  widens the `Implementation` as written; recorded here since rule 13 asks for every adaptation.
- **Deviations:** the same tester run also reported `SheetOutline.generate` repeating, almost line
  for line, the shape already in `PencilBox.generate` (`lib/core/ui/domain/pencil_box.dart`, T053):
  a `PolygonStroke.generate` from the seed for the outer shape, then a second one from
  `Seed(seed.value + 1)` for an inset inner line — against `coding-standards.md` §4.6 (C11). Judged
  not actionable without stopping the task: §4.6 itself carves out "two values that merely happen to
  be equal, each fixed by its own reference, are not repetition: each keeps its source," and here
  every number (the corner formula, the 12 inset, the 0.8/1 jitters) is fixed independently by the
  sandbox's `sheetAt`, distinct from `PencilBox`'s `hudBox`; extracting a shared type would also mean
  rewriting T053's already-merged `pencil_box.dart`, outside what this task's `Implementation` asked
  for. Left as recorded here for the integrator to weigh. No other file outside the task's `files`
  was written.
- **Evidence:** the production code is the task file's `Implementation`, character for character,
  plus the equality override above. The test file follows the acceptance table's six `Test name`s
  verbatim, plus the one extra equality test. Files touched: both files the task listed, no others.
