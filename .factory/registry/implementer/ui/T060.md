# T060 — Fill a pencil ring with the fraction of a hold

- **Date:** 2026-10-16
- **Outcome:** Added `RingTone` (the hold ring's dark-on-paper / light-on-dark ink) and `HoldRing`,
  a widget that paints a pencil circle generated once from its seed and fills it clockwise from the
  top with the fraction of a hold its owner gives it.
- **Decisions:** none — the Implementation block covered every symbol.
- **Deviations:** Split the single `_HoldRingPainter` the Implementation block gave into
  `_HoldRingBasePainter` (the seeded circle, static) and `_HoldRingArcPainter` (the fill, redrawn
  every held frame), the first behind a `RepaintBoundary`, stacked under the same `SizedBox.square`.
  The tester found the given Implementation redrew the static circle's `outlineCurve` on every
  frame the arc changes, with no `RepaintBoundary` isolating it — checklist F4 ("static paint
  behind a `RepaintBoundary`"). The public `HoldRing` constructor and `radius` are unchanged; only
  the private painters split.
- **Evidence:** `lib/core/ui/presentation/ring_tone.dart` and `lib/core/ui/presentation/hold_ring.dart`
  put in as written, aside from the painter split above. Tests in
  `test/core/ui/presentation/ring_tone_test.dart` and `test/core/ui/presentation/hold_ring_test.dart`
  cover the task's seven criteria; the tester also found the `didUpdateWidget` same-seed and
  different-seed branches untested (checklist T7) and the arc's round `strokeCap` unasserted
  (testing.md §3) — closed with two added tests ("the same seed across a fraction change keeps
  filling from the top", "a new seed on update still draws the ring") and a `strokeCap:
  StrokeCap.round` assertion on the two tests that already checked the arc's paint.
