# T075 — Count down the status effects on every body

- **Date:** 2026-10-17
- **Outcome:** `StatusEffects`, the aggregate holding every status effect on every body of the
  zone as three private parallel lists (`_targets`, `_kinds`, `_left`), guarding its invariants
  through `has`, `remaining`, `apply`, `clear` and `advance`; and `StatusEffectEvent`, the sealed
  domain-event family (`StatusStarted`, `StatusCleared`, `StatusExpired`) it returns or fills.
- **Decisions:** none — the task file's `Implementation` was put in as written, aside from the
  deviation below.
- **Deviations:** the literal `advance` expired an effect on `left <= Seconds.zero`. Floating-point
  drift from repeated `dt` subtraction (89–90 steps of `1/60` s, 215–216 of `1/144` s) left a tiny
  positive residual (~1e-15–1e-16) instead of reaching exactly zero, so the "an effect lasts the
  same at any frame rate" criterion failed one frame later than it states. Added a private
  `static const Seconds _epsilon = Seconds(1e-9)` — the same tolerance the task's own criteria use
  for "within 1e-9" — and expire on `left <= _epsilon` instead; well above the drift, well below
  the shortest real status duration (0.5 s). Recorded in `coding-standards.md` §9 style as a `//`
  comment on the constant.

  The tester (T075) found every criterion covered, every applicable checklist item passing, and one
  checklist item (T1: one test file per production file) failing — `status_effect_event.dart` had
  no mirrored test file, only indirect `==` coverage inside `status_effects_test.dart`. Per rule 17
  this was closed in the task's own bounds: added
  `test/features/combat/domain/status_effect_event_test.dart` (inside the module's test root, not
  in the task's `files` list — recorded per the file gradient) asserting `==` and `hashCode` for
  all three events. The tester's non-blocking coverage notes (the absent-entry branch of
  `remaining`, `clear` beside a survivor, `advance` compacting a survivor between two expirations,
  and `apply`'s equal-duration boundary) were also closed by widening `status_effects_test.dart`
  with four more cases, since they test the existing files without touching production code.
- **Evidence:** `lib/features/combat/domain/status_effect_event.dart` (new, as given),
  `lib/features/combat/domain/status_effects.dart` (new, with the epsilon deviation above),
  `test/features/combat/domain/status_effects_test.dart` (new, the task's 11 criteria plus 4 extra
