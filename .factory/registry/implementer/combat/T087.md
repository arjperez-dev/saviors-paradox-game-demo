# T087 — Step the projectiles against the world

- **Date:** 2026-10-17
- **Outcome:** `StepFlights` replaces the stub: each `step(dt)` loads `Flights`, advances every
  flying track, crashes any track `CollisionWorld.cast` finds meeting the world, and otherwise
  offers the bodies `CombatantRoster.near` the track's end, in roster order, to `Flights.meet`
  until one answers; whatever resolved goes to `ReportExchange.flight`, then the flights are saved
  back.
- **Decisions:** none — the task file left no room; the `Implementation` was put in whole.
- **Deviations:** two adaptations, neither of the `Implementation` itself:
  1. To satisfy `lint_command`: the constructor's `: _flights = flights, _roster = roster, _world
     = world, _report = report` assignments trip `prefer_initializing_formals` (an initializing
     formal would force the named constructor parameters to be renamed to
     `_flights`/`_roster`/`_world`/`_report`, breaking the task's own `Interfaces` row), so each is
     followed by a same-line `// ignore: prefer_initializing_formals — private`/`— ditto` comment,
     the same convention `lib/features/combat/application/engagement_queue.dart` and
     `lib/features/combat/domain/engagement.dart` already use for the identical conflict.
  2. The `tester` (registry entry at `.factory/registry/tester/combat/T087.md`) reported that the
     five acceptance-criteria tests never exercise the loop past its first candidate, so the
     Description's "offered, in the roster's order, to `Flights.meet` until one answers" is
     untested, and that the `ignore` comments initially carried no reason, against checklist item
     C10. Both are closed inside this task's own test file: a sixth test, `a flight offers each
     body in roster order until one answers`, registers a same-side body ahead of Akeris at the
     same point so the first `meet` call answers null and the loop falls through to the second;
     the `ignore` comments now each carry a `— private`/`— ditto` reason.
- **Evidence:** `lib/features/combat/application/step_flights.dart` written new, exactly as the
  task's `Implementation` gives it apart from the lint-driven `ignore` comments above.
  `test/features/combat/application/step_flights_test.dart` written new: one test per
  acceptance-criteria row under its exact `Test name`, plus the roster-order fallback test above,
  each exercising `StepFlights` through a real `Flights` and `CombatantRoster`, a
  `MockCollisionWorld` whose `cast` returns null unless a test says otherwise, a
  `MockFlightsRepository` returning the real `Flights`, and a real `ReportExchange` over a
  `MockEventSink` capturing every `publish`, per the task's `Constraints`.
