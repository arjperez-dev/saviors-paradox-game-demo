# T085 — Queue the attacks a body strikes or throws

- **Date:** 2026-10-17
- **Outcome:** `EngagementQueue` replaces the stub, implementing `AttackResolver`: `strike` reads
  the attack and the attacker's immunities, asks the `CombatantRoster` for the bodies within the
  area's half-diagonal reach, and queues one pending `Engagement` per body through
  `EngagementRepository`; `launch` loads `Flights`, launches the missile into it, and saves it back
  through `FlightsRepository`.
- **Decisions:** none — the task file left no room; the `Implementation` was put in whole.
- **Deviations:** one adaptation, not of the `Implementation` itself but needed to satisfy
  `lint_command`: the constructor's `: _roster = roster, _engagements = engagements, _flights =
  flights` assignments trip `prefer_initializing_formals` (an initializing formal would force the
  named constructor parameters to be renamed to `_roster`/`_engagements`/`_flights`, breaking the
  task's own `Interfaces` row), so each is followed by a same-line `// ignore:
  prefer_initializing_formals` comment, the same convention `lib/features/combat/domain/engagement.dart`
  already uses for the identical conflict.

  Open finding (from the tester, registry entry at `.factory/registry/tester/combat/T085.md`):
  checklist item C2 ("dependencies are interfaces, passed through the constructor") does not hold —
  `EngagementQueue`'s constructor takes the concrete `CombatantRoster`, not the `CombatantRegistry`
  contract it also implements, because the use case calls `CombatantRoster.byId`, which
  `CombatantRegistry` does not expose. The task's own `Interfaces` row fixes this exact
  constructor signature, so it cannot be changed from inside this task's files; closing it would
  mean widening `lib/core/contracts/ports/combatant_registry.dart` with a lookup-by-id method, which
  is a contract outside combat's bounds.
- **Evidence:** `lib/features/combat/application/engagement_queue.dart` replaced whole, exactly as
  the task's `Implementation` gives it apart from the lint-driven `ignore` comments above.
  `test/features/combat/application/engagement_queue_test.dart` written new, one test per
  acceptance-criteria row under its exact `Test name`, each exercising `EngagementQueue` through a
  real `CombatantRoster` holding `MockCombatant`s, a `MockEngagementRepository` whose `add`
  arguments are captured, and a `MockFlightsRepository` returning a real `Flights`, per the task's
  `Constraints`.
