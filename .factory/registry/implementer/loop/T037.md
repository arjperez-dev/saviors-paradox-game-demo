# T037 — Test the halts frame by frame inside a Flame game

- **Date:** 2026-10-15
- **Outcome:** Added four tests to `test/integration/loop_frame_test.dart`, joining T009's three
  unchanged tests, exercising `EventQueue`, `WorldHalts`, `StepClock`, `GameLoop` and
  `LoopComponent` together inside a real Flame game: interface systems stepping on while a
  `MapOpened`/`MapClosed` pair halts and frees the world system; two distinct `HaltCause`s
  (`PauseOpened` + `DialogueOpened`) both needing to resolve before the world resumes; an
  `AbilityChosen` (a `WorldResumed` of `HaltCause.abilityChoice`) never freeing a world held by
  `HaltCause.map`; and a `CommandDrain` publishing `PauseClosed` on its third call, freeing the
  world that same frame.
- **Decisions:** the task file carries no `Implementation` section — only `Interfaces` marked
  `uses` and four `Assertion`s — so the test bodies were written straight from the assertions
  against the existing T034–T036 classes, with no production code to put in place. `gameStepping`
  (T009's helper) took the two further optional parameters the task's `Constraints` allowed —
  `interfaceSystems` and `drain` — rather than a new helper, since `GameLoop`'s own constructor
  already exposes them with the same defaults. Two more top-level helpers, `updateFrames` and
  `publishOnCall`, were extracted to keep every new test body within `coding-standards.md` §3's
  20-line function limit, the same gap the tester flagged on T009's tests and that this task's
  tester flagged again on two of these four.
- **Deviations:** none outside the test file — no file outside `files` was touched, and no cited
  reference (`coding-standards.md`, `testing.md`) contradicted the task.
- **Evidence:** all four `Test name`s copied verbatim into `test/integration/loop_frame_test.dart`
  under `group('the loop, frame by frame in a Flame game', …)`, after T009's three. `flutter test`
  (235 tests) and `flutter analyze --fatal-infos` both pass clean; `verify-task` reports
  `implemented`. The `tester` subagent confirmed all four criteria are reached with assertions
  matching their stated behaviour and found no bug in the implementation; it flagged (1) the
  "command drained during a pause" test asserting only the cumulative step count instead of
  checking after each frame that the world stepped only on the third, and (2) two of the four new
  test bodies exceeding `coding-standards.md` §3's 20-line limit. Both are closed: the drained-pause
  test now asserts `worldSteps` after each of the three `game.update` calls (0, 0, 1), and the two
  over-length bodies were shortened under the limit using the new `updateFrames`/`publishOnCall`
  helpers, confirmed by rerunning `flutter test` and `flutter analyze --fatal-infos`.
