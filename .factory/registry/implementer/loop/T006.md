# T006 — Turn each frame's time into the step the systems receive

- **Date:** 2026-10-14
- **Outcome:** New `StepClock` in `lib/core/loop/domain/`: `advance(frame)` clamps `frame` to
  `_maxStep`, returns zero while paused, returns zero and consumes from `_hitstopLeft` while a
  hitstop lasts, and passes through what is left of the frame once the hitstop is spent inside it;
  `holdFor(duration)` extends `_hitstopLeft` only if `duration` is longer than what remains;
  `isHeld` reports paused or mid-hitstop.
- **Decisions:** None — the task's `Implementation` block was put in whole, unchanged; traced the
  arithmetic of every acceptance criterion against it by hand before writing the tests, and it
  holds exactly.
- **Deviations:** None. No file outside `files` was touched.
- **Evidence:** `lib/core/loop/domain/step_clock.dart` written new, exactly as the task's
  `Implementation`. `test/core/loop/domain/step_clock_test.dart` written new, one test per
  criterion, against a plain `StepClock()` or one built with a given `maxStep` — no port, no
  collaborator to mock; `StepClock` is the class under test. `flutter test` (43 tests, whole
  suite) and `flutter analyze --fatal-infos` both clean; `verify-task` passed on the first run.
  The `tester` subagent reviewed the suite against the task's acceptance criteria and
  `08-engineering/checklist.md`: all 8 criteria covered, no checklist item reported failing. It
  flagged one judgment call rather than a failure — whether `StepClock`'s private mutable
  `_hitstopLeft`/`_isPaused` fields fit coding-standards.md §5.1's "a mutable field is allowed only
  inside an aggregate root or a pooled object" given `StepClock` is a `core/loop` clock service,
  not a DDD aggregate — and several untested extras implied by the Description but not required by
  any criterion (an exact tie at the clamp/hitstop boundary, a second `holdFor` after the first
  hitstop has partly decayed, `isHeld` observed from a hitstop alone without a surrounding
  pause/resume, `resume()` with no prior `pause()`). The task's `Implementation` was given verbatim
  with those mutable fields, so there was no decision left for this session to make on the
  flagged ambiguity; both it and the untested extras are left for the planner or architect to
  judge, not blocking.
