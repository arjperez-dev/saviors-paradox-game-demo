# T049 — Hand the window's raw input to core/input

- **Date:** 2026-10-15
- **Outcome:** Added `InputListener`, a `StatefulWidget` wrapping a `Focus`
  and a `Listener` that turns Flutter's key and pointer events into this
  game's `RawInput`s and hands each to the `onInput` it is given: a key the
  `_keys` table holds becomes a `KeyDown`/`KeyUp` (both shift keys mapping to
  `InputKey.shift`, repeats dropped since `_onKey` only reacts to
  `KeyDownEvent`/`KeyUpEvent`), any pointer position change becomes a
  `PointerMoved` before its buttons are compared button by button into
  `ButtonDown`/`ButtonUp`, and a non-zero vertical wheel delta becomes one
  `Scrolled` step by its sign.
- **Decisions:** none — the task file left no room; `Implementation` was
  taken as given. For the widget test, I drove keys with
  `WidgetTester.sendKeyDownEvent`/`sendKeyUpEvent`/`sendKeyRepeatEvent` and
  drove the pointer by constructing `PointerDownEvent`/`PointerMoveEvent`/
  `PointerHoverEvent`/`PointerUpEvent`/`PointerScrollEvent` directly and
  dispatching each with `WidgetTester.sendEventToBinding`, which gives exact
  control over position, delta and the `buttons` bitmask (needed for the
  "second button added while one is held, reported as a move" criterion).
  `InputListener`'s child is a `SizedBox` wrapping a fully transparent
  `ColoredBox`, since `Listener`'s default `HitTestBehavior.deferToChild`
  only registers a hit where a descendant paints something (`Decoration.hitTest`
  always returns true); a bare `SizedBox` with nothing painted under it
  would not have been hit-tested at all, and no pointer event would have
  reached the widget.
- **Deviations:** none against `Implementation`, which compiled and passed
  as written; `lib/core/app/bootstrap.dart`'s `shared_file_notes` block was
  left untouched, for the integrator.
- **Evidence:** `lib/core/input/presentation/input_listener.dart` is as given
  in `Implementation`, verbatim. `test/core/input/presentation/input_listener_test.dart`
  is new, one `testWidgets` per `Assertion` of the acceptance criteria (8),
  each pumping `InputListener` once via a shared `_pump` helper and asserting
  the exact list of `RawInput`s the widget handed to `onInput`. The tester's
  pass confirmed all 8 criteria against their test bodies and every
  `checklist.md` item; it flagged two non-required gaps (the wheel's
  horizontal delta, and releasing one of two held buttons) that no
  acceptance row asks for, so I left them unaddressed.
