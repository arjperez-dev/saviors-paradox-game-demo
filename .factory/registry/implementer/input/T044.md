# T044 — Name the raw inputs the game reads

- **Date:** 2026-10-15
- **Outcome:** Added `InputKey`, `PointerButton` and the `RawInput` sealed family
  (`KeyDown`, `KeyUp`, `ButtonDown`, `ButtonUp`, `PointerMoved`, `Scrolled`) in
  `lib/core/input/domain/`, each with the test the task names, so `core/input` has its own
  key and pointer vocabulary and reads no Flutter type.
- **Decisions:** none.
- **Deviations:** none — the `Implementation` was put in as written and compiled unchanged. After
  the tester's run, two gaps it reported in the test bodies (not in the production code) were
  closed: `raw_input_test.dart`'s equality test did not exercise `KeyUp`'s and `ButtonUp`'s own
  `operator==` (only their cross-type branch, through `KeyDown`'s and `ButtonDown`'s `==`), so cases
  comparing a `KeyUp`/`ButtonUp` against an equal one and against one with a different field were
  added; and `input_key_test.dart` / `pointer_button_test.dart` were missing the reference comment
  the codebase's convention gives an exact-value assertion (`testing.md` §3), so `// 00-game/controls.md
  §1-§4` and `§2` were added over their `expect`.
- **Evidence:** files touched, all listed in the task's `files`: `lib/core/input/domain/input_key.dart`,
  `lib/core/input/domain/pointer_button.dart`, `lib/core/input/domain/raw_input.dart`,
  `test/core/input/domain/input_key_test.dart`, `test/core/input/domain/pointer_button_test.dart`,
  `test/core/input/domain/raw_input_test.dart`. `flutter test`, `flutter analyze --fatal-infos` and
  `verify-task` all pass.
