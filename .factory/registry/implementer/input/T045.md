# T045 — Keep the stack of input contexts

- **Date:** 2026-10-15
- **Outcome:** Added `InputContext` and `InputReading`, the two interfaces of
  design-patterns.md §5, and `InputContexts`, the stack of contexts (menu at
  the bottom, playing while a run lasts, one per standing halt on top), with
  the shared mocks for the module's tests.
- **Decisions:** none — the task file left no room.
- **Deviations:** `flutter analyze --fatal-infos` flagged
  `prefer_initializing_formals` on the `_menu` and `_playing` fields of
  `InputContexts`'s constructor, as written in the task's `Implementation`.
  The public parameter names (`menu`, `playing`) are fixed by the `exports`
  row and differ from the private field names, so an initializing formal
  cannot satisfy both the lint and the interface; each assignment keeps an
  `// ignore: prefer_initializing_formals` with its reason, per
  coding-standards.md §10.
- **Evidence:** `lib/core/input/application/input_context.dart`,
  `input_reading.dart` and `input_contexts.dart` are as given in
  `Implementation`, `input_contexts.dart` with the two `ignore` comments
  above. `test/core/input/mocks.dart` is as given. `test/core/input/application/input_contexts_test.dart`
  is new, one test per `Assertion` of the acceptance criteria, exercising
  the two interfaces through `MockInputContext` from the module's mocks.
