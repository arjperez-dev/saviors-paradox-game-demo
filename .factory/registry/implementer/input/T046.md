# T046 — Translate the playing bindings into commands

- **Date:** 2026-10-15
- **Outcome:** Added `PlayingContext`, the `InputContext` that turns the
  playing-mode `RawInput` into `PlayerCommand`s per `00-game/controls.md`
  §1–§4, with its 19-test suite.
- **Decisions:** none — the task file left no room.
- **Deviations:** none. `lib/core/input/application/playing_context.dart` is
  exactly the `Implementation`; the two lookup-table `switch` expressions are
  exhaustive over `InputKey` with no `_` case, exempt from the 20-line limit
  per the task's `Constraints` and coding-standards.md §3. `PlayerCommand`
  subclasses have no `==` override, so the one test per criterion that
  verifies a non-`const` command (`StartMoving` from `_moveOrStop`,
  `StartAttack`, `ReleaseAttack`, `RaiseShield`, `CycleWeapon`) captures the
  published event with `captureAny()` and asserts its fields with `having`,
  rather than equality on the whole command; the rest, built from compile-time
  literals in the `Implementation`, verify against the matching `const`
  command directly.
- **Evidence:** `test/core/input/application/playing_context_test.dart` is
  new, one test per `Assertion` of the acceptance criteria, built on
  `MockInputReading` and `MockEventSink` from `test/core/input/mocks.dart`.
  `flutter test` (267 tests) and `flutter analyze --fatal-infos` are clean.
