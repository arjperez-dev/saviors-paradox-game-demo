# T098 — Build a valid zone from a kit and a seed

- **Date:** 2026-10-17
- **Outcome:** Added `ZoneFailure` (`zone_failure.dart`, plain enum) and `ZoneFactory`
  (`zone_factory.dart`), the factory that builds a `Zone` from a `BiomeKit` and a `Seed`: up to 600
  attempts, each from `Seed(seed.value + attempt)`, kept at the first layout
  `ZoneValidator(fewestRooms: kit.fewestRooms, fewestDeadEnds: kit.altarCount + 1)` passes, built
  into a `Zone` via `Zone.of`; a sealed `Failure(ZoneFailure.noAttemptFits)` when none fits. All 9
  acceptance-criteria tests pass, plus the whole suite (551 tests) and `flutter analyze
  --fatal-infos` clean.
- **Decisions:** none the task file left open; the `Implementation` was already concrete (the
  seed-search loop, the validator's two numbers, the 600-attempt cap), so the production code is
  the literal block. For the tests, built a small helper (`_zoneOf`/`_zonesOf`) that unwraps the
  `Success` value for seeds 1–10, and a plain neighbour-walk over `RoomView.neighbours` (keyed by
  `EntityId`, since `Zone.rooms` carries no index lookup) for the reachability test, matching
  `testing.md`'s guidance to test a factory through its real collaborators and a fixed seed.
- **Deviations:** none. Every file was put in verbatim from the `Implementation`, compiled and
  passed as written against `BiomeKit`, `ZoneBuilder`, `ZoneValidator`, `Zone.of` and the kernel
  contracts (`Result`, `Seed`, `ZoneNumber`) as they stand on this branch. The tester (run after the
  suite was green) found no gap in any criterion of this task and no checklist item the code fails.
- **Evidence:** `lib/features/dungeon/domain/zone_failure.dart` and
  `lib/features/dungeon/domain/zone_factory.dart` written exactly as the task's `Implementation`
  gives them. `test/features/dungeon/domain/zone_factory_test.dart` written with each test's body
  against its `Assertion`, under its `Test name` verbatim. No file outside the task's `files` was
  touched.
