# T089 — Model a room template as values

- **Date:** 2026-10-17
- **Outcome:** Eleven value objects of the dungeon feature's domain layer —
  `edgesBox`, `ZoneGrid`, `ZoneIds`, `RoomKind`, `SpotKind`, `Passage`,
  `IslandSpan`, `WallSpan`, `DriftPath`, `RoomSpot`, `RoomTemplate` — under
  `lib/features/dungeon/domain/`, each with its test file under
  `test/features/dungeon/domain/`, built test-first against the task's
  `Assertion`s.
- **Decisions:** none; the task left no room the `Implementation` did not
  already fill.
- **Deviations:** none. The tester (full run, see
  `.factory/registry/tester/dungeon/T089.md`) found every applicable
  checklist item passing and no gap against a stated acceptance criterion;
  the minor coverage notes it raised (untested constructor asserts, the
  `walls`/`hasChasm` fields and `widthOn`/`heightOn` not directly exercised,
  `RoomTemplate` inequality shown only through `islands`) all trace to the
  task's own criterion wording, not to an implementer choice, so none is an
  `Open finding:`.
- **Evidence:** Every file matches the task's `Implementation` verbatim.
  The only change from a first draft was in the test bodies, not the
  production code: three `Test name`s that carry an apostrophe — "the
  standard grid is the sanctuary's", "a platform rests at the start of its
  path at its phase's start", "a template's lists cannot be changed" — are
  written with a double-quoted Dart string instead of a single-quoted
  string with an escaped apostrophe, so the source text contains the name
  character for character (an escaped `\'` leaves a backslash in the file
  that `verify-task`'s literal-substring check does not find). Files
  touched: exactly the 20 listed in the task's `files`.
