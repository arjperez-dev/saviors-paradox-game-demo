# T103 — Open the boss room's doors

- **Date:** 2026-10-17
- **Outcome:** Replaced the `BossRoomDoors` stub with the real use case: it loads the zone from
  `ZoneRepository`, asks the root to open its sealed boss-room doors, saves the zone, and, when the
  doors were actually unsealed, publishes `SoundEffectCued(sfx.bossDoor.open)` at the boss room's
  centre.
- **Decisions:** The acceptance test builds the real zone of `Seed(1)` from `ZoneFactory` (as
  `zone_factory_test.dart` already does), and reads the boss room's expected centre from
  `zone.rooms.firstWhere((room) => room.room == zone.bossRoom).bounds.centre` rather than a value
  recomputed by hand, since `Zone.unsealBossRoom()`'s `at` and a room's `RoomView.bounds.centre`
  are built from the same geometry. `SoundEffectCued` has no value `==`, so the publish is
  asserted with `captureAny()` and field checks on the captured event rather than an equality
  match; this needed `registerFallbackValue` for both `SoundEffectCued` and a real `Zone` (`Zone`
  is a `final` class outside its library, so it cannot be `Fake`d — the fallback is a second real
  zone of `Seed(1)`).
- **Deviations:** None against the task's `Implementation`, taken as written. The tester found no
  criterion or checklist gap; it noted the "doors that never sealed" test did not pin the call
  count of `zones.save`, unlike the other two tests — added `verify(() => zones.save(zone)).called(1)`
  there for consistency. No tester finding was left open.
- **Evidence:** `lib/features/dungeon/application/boss_room_doors.dart` taken as written, no
  adaptation needed. Files touched: `lib/features/dungeon/application/boss_room_doors.dart`,
  `test/features/dungeon/application/boss_room_doors_test.dart` (new).
