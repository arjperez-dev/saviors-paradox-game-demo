# T037 — Test the halts frame by frame inside a Flame game

- **Date:** 2026-10-15
- **Outcome:** All four new acceptance-criterion rows have a test under their exact `Test name`, joining T009's three kept-unchanged tests; `flutter test test/integration/loop_frame_test.dart` is green (7/7, verified directly) and `dart format --set-exit-if-changed` / `flutter analyze --fatal-infos` on the file are clean (verified directly). Three of the four new tests assert exactly what their `Assertion` states, traced step by step against `GameLoop.advance`, `StepClock.advance`, `WorldHalts.halt`/`resume` and `EventQueue.deliver`/`subscribe`'s subtype dispatch (`MapOpened`/`PauseOpened`/`DialogueOpened`/`AbilityChosen` each extend `WorldHalted`/`WorldResumed` with their own `HaltCause`, so `queue.subscribe<WorldHalted>`/`<WorldResumed>` in `GameLoop`'s constructor catches them without any extra wiring in the test).
- **Decisions:** no manual test written — the task file carries no `Manual check`.
- **Deviations:** one criterion's test does not assert what its `Assertion` states in full — **"a command drained during a pause frees the world that frame"** (`test/integration/loop_frame_test.dart:185-212`). The `Assertion` is "the world system steps only in the third frame," but the test only checks the cumulative `worldSteps` after all three `game.update` calls (`expect(worldSteps, 1);` at line 210); it never checks `worldSteps` after frame 1 or frame 2 individually. A bug that stepped the world on frame 1 or frame 2 instead of frame 3 (while still landing on a final count of 1) would pass this test undetected. The sibling criterion "two halts hold the world until both end" (lines 150-168) asserts the same kind of "only in the Nth frame" claim correctly, with an `expect` after each `game.update` call — the same pattern here (0 after frame 1, 0 after frame 2, 1 after frame 3) would close the gap.
