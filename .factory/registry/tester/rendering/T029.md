# T029 — Draw the kit's strokes with one reused pencil

- **Date:** 2026-10-15
- **Outcome:** all 4 criteria have a test under its exact `Test name`; `flutter test test/core/rendering/presentation/pencil_test.dart` — 4/4 pass (re-run independently); `flutter analyze --fatal-infos` on both files is clean (re-run independently). `pencil.dart` is verbatim the task's `Implementation` code block, so all ten `Interfaces` symbols match the code exactly. Only 4 of those 10 symbols (`passColor`, `line`, `clipToPolygon`, and implicitly `Pencil`'s constructor) are exercised by any test; `fillPolygon`, `outlinePolygon`, `fillCurve`, `outlineCurve`, `clipToCurve` and `hatch` have zero test coverage.
- **Decisions:** no manual test written — the task file has no `Manual check`.
- **Deviations:** none at the literal-assertion level — each test asserts exactly what its `Assertion` states (pass alpha ≈0.3 within 1e-3; opaque pass alpha exactly 1; a 2.9-wide line's picture has more bytes than an empty one; `getSaveCount()` equals its pre-clip value after one `restore()`).
- **Evidence:**

  **Covered, matching the `Assertion` and the cited reference.** Criterion 1 ("colours a pass by its alpha"): `Pencil.passColor` of an opaque colour and a `QuadraticPass(alpha: 0.3)` gives `.a` within `1e-3` of 0.3 — matches, and 0.3 is the same second-pass alpha `strokes.md` §1 fixes ("a second pass follows it at 30% alpha"), so the reference and the test agree. Criterion 2 ("keeps an opaque pass opaque"): `alpha: 1` gives `.a == 1` exactly — matches. Criterion 3 ("draws a line into a picture"): a `LineStroke.generate(..., width: 2.9, random: StrokeRandom(Seed(1)))` drawn through `Pencil().line(...)` on a `Canvas` over a `PictureRecorder` gives `picture.approximateBytesUsed` greater than an empty recording's — matches the assertion's literal wording and is a reasonable way to prove something was drawn without mocking `dart:ui` directly (`testing.md` §4.1, §5's "presentation" row). Criterion 4 ("restores the canvas after a clip it was asked to save"): one `canvas.restore()` after `clipToPolygon` returns `getSaveCount()` to its pre-clip value — matches, and is the only test that touches the `canvas.save()`/`clipPath()` pairing the Implementation's doc comment promises ("the caller restores it").

  **Not reached — six of ten declared `Interfaces` symbols are never called by any test.** `fillPolygon`, `outlinePolygon`, `fillCurve`, `outlineCurve`, `clipToCurve` and `hatch` appear in the task's `Interfaces` table and in `pencil.dart`, but no test in `pencil_test.dart` invokes any of them. No acceptance criterion names them either — the planner wrote only 4 criteria — so this is not a criterion gap to close, but it is a real gap in what the suite proves about the file: nothing shows `fillPolygon`/`fillCurve` actually switch the shared `_paint` to `PaintingStyle.fill`, that `outlinePolygon`/`outlineCurve`/`hatch` switch it to `PaintingStyle.stroke` with the given `width`, or that `clipToCurve` saves/restores symmetrically like `clipToPolygon` does (only the polygon variant is tested). A regression that swapped `_fill`/`_stroke` inside any of these six methods, or dropped `clipToCurve`'s `canvas.save()`, would pass the whole suite.

  **Not reached — `line`'s two untested inputs.** `line`'s `widthScale` parameter is never exercised with anything but its default `1`; no test shows a non-default `widthScale` actually scales `pass.width` before it reaches `_stroke`. Separately, every test that calls `line` uses `width: 2.9` (≥ `LineStroke._secondPassWidth == 2`), so `line`'s second pass is always present (`line.second != null`); no test exercises a line thin enough (`width < 2`) that `second` is `null`, so the `if (second != null)` branch's false path — "draw only the main pass" — is never taken in any test.

  **A weaker point already implied by the Assertion's own wording.** Criterion 3's assertion ("records a picture whose `approximateBytesUsed` is greater than an empty recording's") is byte-count-only, so it is satisfied whether `line` draws one pass or two, whether `passColor` was applied to the second pass's colour, or whether the stroke widths used are the ones `LineStroke` generated. This is what the criterion literally asks for and is a defensible approach given the project's "no golden images" rule (`testing.md` §5, §8), but it means criterion 3 cannot by itself distinguish a correct two-pass draw from a degenerate one-pass draw of the wrong colour — the same limit `T028`'s registry entry noted for `Path.contains` and `.close()`.
