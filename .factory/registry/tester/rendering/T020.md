  Checklist item this task's code fails: **A10** / architecture.md §6.1 ("No allocation in the per-frame path of a hot loop… chains" are named explicitly as part of that hot loop). `Vec2` (`lib/core/contracts/kernel/vec2.dart`) is a `final class`, not a zero-cost extension type, so every `+`, `-`, `scaled` and `distanceTo` call heap-allocates a new instance. `layOut` (`lib/core/rendering/domain/chain_links.dart:46-58`) is documented to run every frame per chain: `from.distanceTo(to)` (line 47) allocates once via `this - other`; `sag = Vec2(...)` (line 56) allocates once; `(from + to).scaled(0.5) + sag` (line 57) allocates three more. Inside the per-link loop, `_place` (lines 60-70) calls `_curve` (lines 72-75) once per link, and `_curve` allocates five more `Vec2` per call (three `scaled`, two `+`) — so a 70-su chain (10 links) allocates on the order of 55 `Vec2` objects on every `layOut` call. The task's own `Constraint` ("`layOut` allocates nothing beyond the `Vec2` values of its arithmetic") licenses exactly this, but it contradicts the cited architecture.md §6.1, which names no such exception and lists chains by name as the hot-loop case the rule exists for; per the tester's rule that a cited reference wins over a contradicting constraint, this is reported as a gap, not resolved here.
