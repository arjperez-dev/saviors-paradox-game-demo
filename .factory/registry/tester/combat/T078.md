- **Date:** 2026-10-17

- **Decisions:** none — the task file has no `Manual check`, so no manual test was written.
- **Deviations:** none against this task's criteria, literally read. Branches and boundaries the 20 tests do not reach:
  - **Pool eviction order beyond the first cycle.** "a launch into a full pool reuses the oldest flight" proves only the very first eviction (id 1 is dropped, id 65 survives). `_freeOrOldest` picks the slot whose `_id.value` is smallest; no test launches a 66th or 67th flight to prove the *second* and *third* evictions still pick the correct slot once a reused slot's id is no longer monotonic with its physical position — the part of the pool invariant most likely to regress silently.
  - **Simultaneously-flying flights.** Every test but the pool-fill one keeps exactly one flight airborne at a time. No test launches two or more flights with different velocities and asserts `advance` moves each independently (e.g. via two `trackOf` calls after one `advance`), so a bug that moved only `_slots[0]` or double-moved a flight would not be caught.
  - **The 4 s lifetime boundary.** Only a single `advance(Seconds(4))` is tried. No test checks a flight still flying just under the boundary (e.g. two steps summing to `Seconds(3.99)`) nor accumulation across several small `dt` steps (the shape a real frame loop takes), so an off-by-one in `_age >= Flights.lifetime` or in `Seconds` addition would not be caught.
  - **Slot reuse after natural expiry**, as opposed to forced eviction from a full pool: no test lets a flight expire by age and then launches a new one to show the now-free slot (not the reused-oldest slot) is picked.
  - **Affliction immunity combinations on a turn.** The ice- and fire-shield turn tests both use a thrower with `Immunities.none`; `Affliction.byShield`'s `immunities.toIce`/`immunities.toFire` branches (slowed-instead-of-frozen, null-instead-of-burning) are never exercised through `Flights.meet`.
  - **The tie-break in `_turn` when `throwerAt.x == _at.x`** (`towards == 0`, defaulting to `+speed`) is not tried.
  - **Non-perfect block with the ice or fire shield** is not tried; only the sacred shield's non-perfect path is asserted (the perfect-sacred, perfect-ice and perfect-fire turn/affliction paths are covered separately).
