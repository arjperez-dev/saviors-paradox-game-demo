# T058 — Frame a box in pencil on paper

- **Date:** 2026-10-16
- **Outcome:** all 15 criteria rows have a matching, passing test, named verbatim to the acceptance
  table, across `flash_kind_test.dart`, `ink_flash_test.dart`, `frame_look_test.dart`,
  `frame_style_test.dart` and `ink_frame_test.dart`.
- **Decisions:** none — no `Manual check` in the task file, so no manual test written.
- **Deviations:** none the tests reach as stated; one gap found outside the acceptance table, in
  checklist **F4** (below).
- **Evidence:** traced each criterion's `Test name` against `lib/core/ui/presentation/`:
  - "a denied flash lasts 0.35 s and a done one 0.4 s" (`flash_kind_test.dart`) — asserts
    `FlashKind.denied.duration`/`.done.duration` as exactly 350/400 ms, matching
    `06-ui/pause-menu/pause-menu.md` §7 lines 184–185 ("action done … 0.4", "denied … 0.35"), named
    in `flash_kind.dart`'s comments.
  - "flashes are equal by kind and serial" / "a negative serial is refused" (`ink_flash_test.dart`)
    — value equality and the `assert(serial >= 0)` both exercised.
  - "each look carries its paper at rest and under the mouse" (`frame_look_test.dart`) — all 5
    `FrameLook` values checked against `InkThemeData`'s fields pairwise, as the table states.
  - "styles are equal by value" (`frame_style_test.dart`) — `seed`, `look`, `focused`, `hovered`
    each independently break equality.
  - `ink_frame_test.dart`'s 11 tests each match their row: layout size in hu at 2560×1440; paper
    fill + thin frame at rest (`InkThemeData.paperFill`/`frameColour` at width 1.7); hovered paper
    (`paperFillHovered`); focused thick frame + inner line (`Palette.ink` at width 3.6,
    `focusInnerColour` at width 1, and no width-1.7 path); each `FrameLook`'s own paper
    (`faintFill`, `Palette.paperLight` for `keyCap`, `questionFill`); the dashed empty box (fill
    `dashedFill`, `DashedOutline.along(…, on: 7, off: 6).dashes.length` dash paths at width 1.4, no
    width-1.7 path); the focused dashed box adding the width-3.6 outline after the dashes; the
    flash fading the width-3.6 path from `Palette.ink` at alpha 0.5 (175 ms into the 350 ms denied
    flash) to gone (375 ms in, past the duration); the same `InkFlash` given again, and a flash
    given on the very first build, both producing no width-3.6 path; the child's top-left matching
    the frame's. All colours and widths are `InkThemeData`'s, and stroke widths are compared through
    `Float32List.fromList([…]).first` as the table's header specifies. The `paints` call order in
    each test matches `_InkFramePainter.paint`'s order (fill → frame/dashes → flash).

  Not reached by any test, and not named by an acceptance criterion:
  - The flash overlay's own geometry: `_FrameStrokes.flash` is a second `PencilBox`, generated at
    `size + 8` hu and seed `+ 5`, drawn translated by `(-4, -4)` so it sits 4 hu out from the box on
    every side (`ink_frame.dart` lines 98–101, 279, 382; the 06-ui sandbox's `pmBox`). No test checks
    this offset or its geometry — only the flash path's colour, width and timing — so a sign or
    arithmetic error in that translate would not be caught. The acceptance table's own wording for
    "a new flash fades the thick frame out over its duration" does not ask for this either, so this
    is not a gap against a stated criterion, only a branch of the `Implementation` no test enters.
  - Whether `_strokes` is kept (not regenerated) across a rebuild that changes only `focused` or
    `hovered` — the `Constraints` section's "Strokes are generated in `initState` and again only
    when `size` or `style.seed` changes" (`ink_frame.dart`'s `didUpdateWidget`, lines 48–53, and
    `_InkFramePainter.shouldRepaint`'s `identical(oldDelegate.strokes, strokes)`, lines 223–226).
    By inspection the code is correct, but nothing exercises the "unrelated rebuild keeps the same
    strokes" branch (checklist **G5**).

  Checklist: **F4** fails — `_InkFrameState.build` (`ink_frame.dart` lines 68–84) puts the
  `CustomPaint` directly under `SizedBox`, with no `RepaintBoundary`. `_InkFramePainter` is
  constructed with `repaint: flash` (line 125), so every tick of a flash (350–400 ms, ~21–24 frames
  at 60 fps) re-runs the *whole* `paint()` — the paper fill and the thin/thick frame, which do not
  change during the flash, are redrawn on every one of those frames alongside the fading overlay,
  and without a boundary the repaint is not contained to this widget's own layer. `InkFrame` is
  described as the box "every button, key cap and question is drawn in", so this cost is paid by
  every flashing box on a screen, each frame of its flash. [standards §11.4, checklist F4]
