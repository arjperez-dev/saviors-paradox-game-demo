# T056 — Move the focus through a screen's rows of choices

- **Date:** 2026-10-16
- **Outcome:** all 7 criteria have a matching, passing test; `flutter test` green (7/7);
  `flutter analyze --fatal-infos` and `dart format --set-exit-if-changed` both clean.
- **Decisions:** none — no `Manual check` in the task file, so no manual test written.
- **Deviations:** none the tests reach; two checklist/reference gaps found (below).
- **Evidence:** `flutter test test/core/ui/domain/focus_group_test.dart` → 7 passed, 0 failed,
  names verbatim to the acceptance table:
  - "the first choice is the first of the first row" — `group.first` is `'a'`.
  - "a move along a row goes to the next choice" — `moved('a', MoveFocus(columns: 1, rows: 0))`
    is `'b'`; `moved('b', MoveFocus(columns: -1, rows: 0))` is `'a'`.
  - "a move past the end of a row stays" — `moved('c', columns: 1)` is `'c'`;
    `moved('a', columns: -1)` is `'a'`.
  - "a move down keeps the column as far as the row reaches" — `moved('c', rows: 1)` is `'d'`;
    `moved('d', rows: 1)` is `'e'`.
  - "a move down a row of the same length keeps the column" — a separate `[a, b], [c, d]` group,
    `moved('b', rows: 1)` is `'d'`.
  - "a move past the first or last row stays" — `moved('b', rows: -1)` is `'b'`;
    `moved('f', rows: 1)` is `'f'`.
  - "a choice not in the group moves as the first one" — `moved('z', rows: 1)` is `'d'`.

  Each test body matches the `ttMove` reference the test file cites in its own comment
  (`06-ui/sandbox/sandbox.html`): same clamp-at-the-edges behaviour, same "keep the column as far
  as the row reaches" rule, checked by hand against `ttMove`'s `r`/`c` clamping (`row`/`column`
  clamped against the row the focus starts in, then re-clamped against the row it lands on).

  Not reached by any test, and not required by an acceptance criterion: a move with both `columns`
  and `rows` non-zero at once (`ttMove`'s own `d` is always a single axis, so the reference gives
  no case to check this against — nothing to flag, just unreached); seeds or rows beyond the three
  given by the fixture.

  Checklist/reference findings for the implementer:
  - **testing.md §5 (value object: invariants)**: `FocusGroup`'s constructor has two `assert`s —
    `rows.isNotEmpty` and `rows.every((row) => row.isNotEmpty)`
    (`lib/core/ui/domain/focus_group.dart` lines 11–12) — and no test in
    `test/core/ui/domain/focus_group_test.dart` constructs a `FocusGroup` with an empty row list or
    a row with no choices to see either assert fire. Neither is an acceptance criterion, so this is
    a coverage gap against the testing reference, not a failing criterion.
  - **architecture.md §4 (value object: "equal by value")**: the task's own Description calls
    `FocusGroup` "an immutable value (architecture §4)"; `architecture.md` §4 fixes a value object
    as "equal by value", but `FocusGroup` (`lib/core/ui/domain/focus_group.dart`) overrides neither
    `operator ==` nor `hashCode`, so two `FocusGroup`s built from equal rows are not equal to each
    other. The same gap was already flagged for `PencilBox` (T053) and `SheetOutline` (T055) in
    this module's prior tester reports.
