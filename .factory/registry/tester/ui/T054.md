# T054 — Dash a closed outline from its first corner

- **Date:** 2026-10-16
- **Outcome:** all 6 criteria have a matching, passing test; `flutter test` green (6/6); `dart format`
  and `flutter analyze --fatal-infos` clean on both files.
- **Decisions:** none — no `Manual check` in the task file, so no manual test written.
- **Deviations:** none the tests reach. One gap, not tied to any acceptance criterion or checklist
  letter: the task's Description calls `DashedOutline` "a value object (architecture §4)", whose
  rule (`architecture.md` §4 table) is "immutable; equal by value; validates itself in its
  constructor; transitions return a new value" — `dashed_outline.dart` overrides neither
  `operator ==` nor `hashCode`, and `DashedOutline.along` validates nothing (no guard on `on <= 0`
  or `off < 0`, which, given the factory's `for (start = 0.0; start < perimeter.length; start += on

  these inputs. This is not a gap introduced by the implementer: the task file's own `Implementation`
  block is reproduced verbatim in the production file, so the missing guard is in what the task
  specified, not what the implementer added — reported for visibility, not as something this task's
  closing should fix unilaterally.
- **Evidence:** `flutter test test/core/ui/domain/dashed_outline_test.dart` → 6 passed, 0 failed,
  names verbatim to the acceptance table:
  - "the first dash starts at the first corner" — outline A, `on: 7, off: 6`, first dash exactly
    `[(0, 0), (7, 0)]`.
  - "a dash ending on a corner stops there" — second dash exactly `[(13, 0), (20, 0)]`.
  - "a dash going round a corner keeps the corner" — third dash exactly `[(20, 6), (20, 10), (17,
