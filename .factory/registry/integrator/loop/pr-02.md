```text
## Summary

This wave widens the loop's single pause cause into a set of five: `WorldHalts` lets `pauseMenu`,
`map`, `dialogue`, `abilityChoice` and `cinematic` each hold the world independently, and
`StepClock` asks that set in `isHeld`/`advance` instead of a pause flag of its own. `GameLoop` now
also steps a list of interface systems after the world, on the frame clamped to the maximum step
but never halted or held, through a new `CommandDrain` that drains `core/input`'s commands into the
queue before either list steps. It deliberately registers no interface system of its own; the empty
list stays for later waves to fill.

## Scrutinise

- `GameLoop` steps the interface systems every frame on a step that no halt or hitstop ever zeroes;
  nothing in the loop stops a future interface system from mutating game state, so each one added
  later needs checking by hand against "a widget's own animation changes no game state"
  (coding-standards.md §8).
- `WorldHalts.resume` frees a cause whenever that cause is passed in, regardless of which screen
  raised the matching halt; two screens sharing one `HaltCause` would let either one's resume free
  the other. Worth confirming each of the five screens pairs its own cause one for one.
```
