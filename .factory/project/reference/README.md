# Savior's Paradox — references

This folder says, with numbers and pictures, what `../VISION.md` says in prose: how the game's code
is written, and how every character, zone, item, piece of UI and sound looks, moves and sounds.
Every piece is made with the operator and approved by the operator before any agent reads it.

**This file is the index the agents trust.** A piece exists for an agent only if the table below
marks it `approved`. Everything else in the folder — drafts, work in progress, `_plan/` — does not
exist for them.

---

## 1. Authority

| Question | Who answers |
|---|---|
| What the game is, its controls and its gameplay numbers (speeds, damage, cooldowns, hitboxes) | `VISION.md`, then the code built from it |
| How something looks, moves, sounds or is laid out | the approved reference for it |
| How code is written | `08-engineering/` |
| A reference and the code disagree | the reference wins, and the code is fixed |
| A reference and `VISION.md` disagree | nobody chooses: the operator settles it, and one of the two is revised |
| A reference is ambiguous | the agent stops and says so; it never invents the missing value |

**Inside a piece:** its `contract.md` holds the rules and numbers; its `sandbox/sandbox.html` is the
playable look; its `sprites/sheet.png` is the pose sheet exported from the sandbox. Where the contract and the sandbox
disagree on how something **looks or moves**, the sandbox wins, and the contract has a defect to fix.

## 2. Who reads what

Fixed by `docs/CONTEXT_POLICY.md` §2.1–§2.2. No agent writes here.

| Agent | Reads |
|---|---|
| translator | this index and every approved piece, to keep `VISION.md` faithful to them |
| architect | this index and every approved piece; the code rules of every `CLAUDE.md` derive from `08-engineering/` |
| planner | this index and every approved piece; every task lists the exact paths it is built against in `references` |
| implementer | every approved piece of `08-engineering/`, and the paths its task lists in `references` |
| tester | every approved piece of `08-engineering/`, and the paths its task lists in `references`; it holds every task against `08-engineering/checklist.md` |
| integrator | nothing |

Paths in this file are relative to this folder. In a task file they are written from the repository
root: `.factory/project/reference/03-characters/akeris/contract.md`.

## 3. Status

| Status | Means |
|---|---|
| `draft` | being made; no agent reads it |
| `review` | published for the operator to try; no agent reads it |
| `approved` | the operator approved it on the date given; agents read it |
| `superseded` | replaced by the piece named in its notes; no agent reads it |

A change to an approved piece puts it back to `review` until the operator approves it again. A task
already planned against the old version is replanned by the planner.

**Sprites and weapons are PNGs.** A character's `sprites/` holds everything exported from its sandbox
as images: `sheet.png` (the pose sheet), single poses and frames, frame sheets of its animations and
effects, and the callouts that are its own. Its `weapons/` holds, beside each `<weapon>.md`, the
weapon's PNGs: the weapon alone, and a sheet of how the character carries, draws, swings and
sheathes it. An effect in `02-art-direction/fx/<effect>/` has the same `sprites/`. Every PNG is
exported from a sandbox, never drawn by hand, and is exported again when the sandbox changes.

**Weapons.** How a weapon looks in a character's hands and how that character draws, swings and
sheathes it lives in `03-characters/<name>/weapons/`, because it is animation. What the weapon is as an
object — its stats, how it is found, its inventory icon — lives in `05-items/`, and links to the
character's `weapons/` file. An enemy's weapon that the player never picks up has no `05-items/` entry.

Folder and file names are English, lowercase and kebab-case. Zones are numbered in the order they
are played: `zone-1-suspended-sanctuary`.

## 6. How a piece is made

1. Start from its template in `_templates/`, and from what `VISION.md` says about it.
2. A character or a zone gets a playable `sandbox/sandbox.html`, built from the Akeris sandbox and drawn with
   the same static stroke: nothing trembles.
3. It is checked with headless-browser screenshots, published for the operator to try, and iterated
   (`review`).
4. Once the operator approves it, its `contract.md` is written with the numbers, its PNGs are exported
   from the sandbox into `sprites/` and `weapons/` (the pose sheet with key `P`, frame sheets, single
   poses, weapons, its own callouts), and its row here becomes `approved` with the date.

Sandbox tools every sandbox keeps: the seeded static stroke, the pose sheet (`P`), deterministic
test scenarios selected by `#name` in the URL (`#name@seconds` to freeze another instant), frame-sheet
exports (`#hoja-<name>`), and headless-browser screenshots.

## 7. Conventions every piece follows

- **Units.** Drawings are measured in sandbox units (**su**): Akeris standing is 192 su tall. In the
  game, one tile is 32 world units and y grows downward; a length in su becomes world units by
  multiplying by `k = Akeris's standing height in world units ÷ 192`
  (`02-art-direction/ART_DIRECTION.md` §3).
- **Time** is in seconds; an animation's duration is the one the game logic gives it, and the
  reference gives its shape and its default.
- **Nothing trembles.** Every stroke is generated once from a fixed seed; only real motion moves.
- **Player-visible text** is written as translator keys with their English text; the game never
  hard-codes a string.
- **Controls** are defined only in `VISION.md`; `00-game/controls.md` copies them as a table and
  adds nothing. A sandbox's keys are browser stand-ins.
